## “Linear” in which quantities?

It is tempting to think linear regression can only draw straight lines and planes. That is not quite right. Look at what the least-squares machinery actually needed: predictions of the form $X\theta$, i.e. *linear in the unknown parameters*. The columns of $X$ can be any fixed functions of the raw inputs that we compute before fitting.

So create new features from old ones:

$$
\hat y = \theta_0 + \theta_1x_1 + \theta_2x_1^2, \qquad x_2 := x_1^2 \;\;\Longrightarrow\;\; \hat y = \theta_0 + \theta_1x_1 + \theta_2x_2.
$$

$$
\begin{gathered} \hat y = \theta_0 + \theta_1x_1 + \theta_2x_1^2 + \theta_3x_1^3, \qquad x_2 := x_1^2,\; x_3 := x_1^3 \\ \Longrightarrow\;\; \hat y = \theta_0 + \theta_1x_1 + \theta_2x_2 + \theta_3x_3 \;\;\text{(ordinary multiple regression)}. \end{gathered}
$$

In general, choose a feature map $\phi(x) = (1, x, x^2, \dots, x^d)\T$ and fit $\hat y = \theta\T\phi(x)$. Each row of the design matrix becomes $(1, x_j, x_j^2, \dots, x_j^d)$, and every formula from lessons 4–6 applies unchanged.

<Callout kind="definition" title="Linear vs nonlinear regression">
A model is **linear regression** if the prediction is a linear combination of fixed features with the unknown parameters as weights — however curved it is in $x$. **Nonlinear regression** has parameters entering nonlinearly, such as $\hat y = \dfrac{\theta_1 x}{\theta_2 + x}$: no fixed column can carry $\theta_2$ in the denominator, so the normal equations no longer apply.
</Callout>

<Callout kind="theorem" title="Why training error cannot increase with degree">
The degree-$(d+1)$ family contains the degree-$d$ family: set $\theta_{d+1} = 0$. Least squares picks the best member of its family, so the bigger family’s best training SSE is at most the smaller one’s. This guarantee is about *training* error only — it says nothing about new data.
</Callout>

That gap between training and held-out behaviour is the central question: *how do we control the complexity of the model to avoid overfitting?* Lessons 10 (regularisation), 11 (validation) and 13 (bias–variance) answer it from three directions.

## Categorical inputs: indicator variables

Regression needs numbers, but many inputs are categories. An **indicator** (binary, dummy) variable takes the value 1 if a condition holds and 0 otherwise. Let $D = 1$ if a patient takes a drug. To model blood pressure while holding age fixed:

$$
\hat y = 70 + 5D + 0.44\,\text{Age}.
$$

Substituting the two values: $D=0$ gives $70 + 0.44\,\text{Age}$; $D=1$ gives $75 + 0.44\,\text{Age}$. So “taking the drug” corresponds to a predicted difference of 5 units *at any fixed age* — two parallel lines.

What if the drug’s effect depends on age? Add an **interaction** feature $z = D\times\text{Age}$:

$$
\begin{gathered} \hat y = 70 + 5D + 0.44\,\text{Age} + 0.21\,z \\ \Longrightarrow\quad D=0:\; \hat y = 70 + 0.44A, \qquad D=1:\; \hat y = 75 + 0.65A. \end{gathered}
$$

Now the gap is $5 + 0.21A$: at age 40 it is 13.4. The model is still linear in its four parameters — $z$ is just another column computed before fitting.

<Callout kind="warning" title="Two interpretation traps">
With the interaction, the coefficient 5 is the predicted difference *at age 0*, not “the drug effect”. Report the gap at the ages you care about.

The regression describes a conditional association in the data. Calling it a *causal* effect of the drug needs more than the equation — e.g. a randomised experiment.
</Callout>

<Callout kind="intuition" title="More than two categories (going deeper)">
A category with $k$ levels (e.g. suburb A, B, C) needs $k-1$ indicators, with the omitted level as the baseline absorbed by the intercept. Using all $k$ indicators *and* an intercept makes the indicators sum to the ones column — a rank-deficient design (lesson 5), sometimes called the dummy-variable trap.
</Callout>

<Callout kind="key">
Linear regression is linear in the *parameters*, not in the inputs. Transformed features (powers, logs, indicators, products) are just extra columns of $X$, so curves, group shifts and interactions all use the same least-squares machinery. Bigger feature sets always fit training data at least as well — which is exactly why we need a way to control complexity.
</Callout>
