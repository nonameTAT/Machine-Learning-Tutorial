## Why iterate when there is a formula?

Lesson 5 solved least squares exactly. So why learn an iterative method? Three reasons. Solving the normal equations costs roughly $O(mn^2 + n^3)$, which becomes expensive with very many features. Most other losses you will meet (logistic regression, neural networks) have *no* closed-form minimiser. And data may arrive in a stream, too large to hold at once. Gradient descent needs only one thing: the ability to compute the slope of the loss at the current point.

<Callout kind="intuition">
You are on a foggy hillside and want the valley floor. You cannot see the valley, but you can feel which way the ground slopes under your feet. Take a step downhill; feel again; repeat. The gradient is “which way is up, and how steeply”; the learning rate is your stride length.
</Callout>

## The update rule

Starting from some $\theta^{(0)}$, repeat:

$$
\theta_i^{(t+1)} := \theta_i^{(t)} - \alpha\,\frac{\partial}{\partial\theta_i}J(\theta^{(t)}) \qquad\text{for every } i, \qquad\text{i.e.}\qquad \theta^{(t+1)} = \theta^{(t)} - \alpha\nabla J(\theta^{(t)}).
$$

$\alpha > 0$ is the **learning rate** (step size). Why the minus sign? The gradient points in the direction of steepest *increase*; for a small enough step, moving against it decreases $J$ (to first order, $J(\theta - \alpha\nabla J) \approx J(\theta) - \alpha\|\nabla J\|^2$).

<Callout kind="warning" title="Update all coordinates simultaneously">
Compute the whole gradient from the *old* $\theta^{(t)}$, then update every component. Overwriting $\theta_0$ and then using the new value to compute $\theta_1$’s update is a different (and here unintended) algorithm.
</Callout>

## Working out the gradient

<Steps>
Start with a single example $j$. Its loss is $(y_j - h_\theta(\bx_j))^2$ with $h_\theta(\bx_j) = \sum_{i=0}^{n}x_{ji}\theta_i = \bx_j\T\theta$ and $x_{j0} = 1$.

<Step title="Chain rule on one squared residual">
$$
\frac{\partial}{\partial\theta_i}\big(y_j - h_\theta(\bx_j)\big)^2 = 2\big(y_j - h_\theta(\bx_j)\big)\cdot\big(-x_{ji}\big) = -2\big(y_j - h_\theta(\bx_j)\big)x_{ji}.
$$
</Step>

<Step title="Plug into the update: the LMS rule">
$$
\theta_i := \theta_i + 2\alpha\big(y_j - h_\theta(\bx_j)\big)x_{ji} \qquad (\text{every } i).
$$

This is the **least mean squares** (LMS) rule. Read it: nudge each weight in proportion to the error times the input that weight multiplies. Positive error (under-prediction) with positive $x_{ji}$ → increase $\theta_i$.
</Step>

<Step title="Average over all m examples: batch gradient descent">
$$
J(\theta) = \frac1m\sum_{j=1}^m (y_j - \bx_j\T\theta)^2 \;\Rightarrow\; \theta_i^{(t+1)} = \theta_i^{(t)} + \alpha\,\frac2m\sum_{j=1}^m\big(y_j - h_{\theta^{(t)}}(\bx_j)\big)x_{ji}.
$$

$$
\text{Matrix form:}\qquad \theta^{(t+1)} = \theta^{(t)} + \frac{2\alpha}{m}X\T\big(\by - X\theta^{(t)}\big).
$$

For the intercept ($x_{j0} = 1$) the update is proportional to the *mean residual* — the same quantity the intercept’s normal equation sets to zero.
</Step>

<Step title="Or update after every example: stochastic gradient descent">
$$
\text{for } j = 1 \text{ to } m:\quad \theta_i := \theta_i + 2\alpha\big(y_j - h_\theta(\bx_j)\big)x_{ji} \quad(\text{every } i)
$$

Repeat the loop over the data until convergence. Each update uses one example’s gradient as a cheap, noisy stand-in for the full gradient. Later examples see the updated θ.
</Step>
</Steps>

## Worked example: one step of each

Data $(x, y) = (0, 1), (2, 3)$, start at $\theta = (0, 0)\T$, $\alpha = 0.1$, loss = MSE.

$$
X = \begin{bmatrix}1 & 0\\ 1 & 2\end{bmatrix},\quad \be = \by - X\theta = \begin{bmatrix}1\\ 3\end{bmatrix},\quad \nabla J = -\frac{2}{2}X\T\be = -\begin{bmatrix}1 + 3\\ 0 + 6\end{bmatrix} = \begin{bmatrix}-4\\ -6\end{bmatrix}.
$$

$$
\text{Batch step: } \theta^{(1)} = \begin{bmatrix}0\\0\end{bmatrix} - 0.1\begin{bmatrix}-4\\-6\end{bmatrix} = \begin{bmatrix}0.4\\ 0.6\end{bmatrix}.
$$

New predictions $(0.4, 1.6)$, so the MSE falls from $(1^2 + 3^2)/2 = 5$ to $(0.6^2 + 1.4^2)/2 = 1.16$. Better, not yet optimal (the optimum fits both points exactly: $\hat y = 1 + x$).

**SGD step on the first example only**: $\theta + 2(0.1)(1 - 0)(1, 0)\T = (0.2, 0)\T$. Different, because it used one example instead of the average of both.

## Choosing the learning rate

- **Initialisation:** start anywhere (e.g. random). For least squares the loss is convex, so every convergent run reaches the same minimum.
- **Too small** an $\alpha$: correct direction but painfully slow. **Too large**: overshoot, oscillate, possibly diverge.

For the quadratic MSE loss we can say exactly where the boundary is. Write $A = X\T X/m$. Then $\theta^{(t+1)} - \hat\theta = (I - 2\alpha A)(\theta^{(t)} - \hat\theta)$, so the error shrinks along each eigen-direction of $A$ by a factor $|1 - 2\alpha\lambda_k|$. Convergence needs every factor below 1:

$$
0 < \alpha < \frac{1}{\lambda_{\max}(A)}, \qquad \text{and the slowest direction shrinks by } |1 - 2\alpha\lambda_{\min}| \text{ per step.}
$$

A large ratio $\lambda_{\max}/\lambda_{\min}$ (the condition number) forces a small $\alpha$ for stability *and* makes the slow direction slow. Centring and scaling features reduce that ratio — a practical reason the pipeline includes feature scaling.

## Batch versus stochastic

|  | Batch GD | Stochastic GD (LMS) |
| --- | --- | --- |
| One update uses | all m examples | one example |
| Cost per update | $O(m(n+1))$ | $O(n+1)$ |
| Updates per pass over data | 1 | m |
| Path | smooth, deterministic | noisy, depends on example order |
| Near the minimum (fixed α) | converges | keeps fluctuating around it |

In short: SGD is much less costly than batch gradient descent, but it may never converge exactly to the minimum. Be precise about “less costly”: it is cheaper *per update*, and often makes useful progress before batch GD has finished its first full pass. In practice the learning rate is decreased over time (or mini-batches are used) so that SGD settles down.

<Callout kind="note" title="Watch the loss scaling">
If the loss is $\SSE$ instead of $\MSE$, the gradient is $m$ times larger, so the same numerical $\alpha$ takes $m$-times bigger steps. Some texts use $\tfrac{1}{2m}\SSE$ to remove the 2. Always differentiate the loss actually written down.
</Callout>

## SGD up close: one loss curve per example

The MSE is an average of per-example losses, and differentiation is linear, so the full gradient is the average of the per-example gradients:

$$
J(\theta) = \frac1m\sum_{j=1}^m \ell_j(\theta), \quad \ell_j(\theta) = \big(y_j - h_\theta(\bx_j)\big)^2 \qquad\Longrightarrow\qquad \nabla J(\theta) = \frac1m\sum_{j=1}^m \nabla\ell_j(\theta).
$$

Batch GD follows $\nabla J$. An SGD step follows a single $\nabla\ell_j$. If $j$ is drawn uniformly at random, $\mathbb{E}_j[\nabla\ell_j(\theta)] = \nabla J(\theta)$, so the SGD direction is right *on average* (an unbiased estimate). Any single step can still point well away from it.

To draw this, the lab below keeps one parameter. It uses the running example with $x$ centred, holds the intercept at its optimum (8), and learns only the slope $\theta$. Each example is then a parabola $\ell_j(\theta) = (r_j - \theta c_j)^2$ with $c_j = x_j - 7$ and $r_j = y_j - 8$, and its gradient $g_j(\theta) = -2(r_j - \theta c_j)c_j$ is a straight line.

<Option>It increases. <Why>The update is 2α · (positive) · (negative) \< 0.</Why></Option>

<Callout kind="key">
Gradient descent repeatedly steps against the gradient: $\theta \leftarrow \theta - \alpha\nabla J$. For MSE, $\nabla J = -\tfrac2m X\T(\by - X\theta)$. Batch GD averages all examples per update; SGD (LMS) uses one at a time — cheaper and noisier. The learning rate trades speed against stability, and for least squares the stability limit is set by the largest eigenvalue of $X\T X/m$, which feature scaling improves.
</Callout>
