## From predicting a number to choosing a class

Week 1 asked how to predict a number. Week 2 asks how to choose a **class** — sometimes by first estimating how probable each class is. The running example is a fish-packing plant that wants to sort sea bass from salmon automatically. Sensors measure *features* such as lightness and width; the species is the *target*.

A **classifier** is a function from an input to one of a finite set of classes. With two classes we write the labels as $y \in \{0, 1\}$, but these are *names*: coding salmon as 0 and sea bass as 1 does not make species a continuous quantity, and nothing is “halfway between” them.

<Callout kind="note" title="Same structure as Week 1">
Choose a representation (features), learn from labelled training data, and judge the predictions on genuinely held-out observations. What changes is the kind of output — and therefore the losses and the evaluation measures.
</Callout>

## Two ways to build a classifier

Looking at the fish scatter plot suggests two quite different ideas.

|  | Discriminative | Generative |
| --- | --- | --- |
| Idea | Find a boundary that separates the classes. | Describe what each class looks like, one class at a time. |
| What it learns | $P(y \mid \bx)$ | $p(\bx \mid y)$ |
|  | or just a decision rule | and the class prior $P(y)$ |
| How it predicts | which side of the boundary / which class is more probable | which class model the query is more similar to, via Bayes’ rule |
| This week | linear classifier, logistic regression, k-NN | idea only (Naive Bayes comes later) |

A generative model learns $p(\bx \mid y)$ and $P(y)$, so it effectively knows the joint distribution $p(\bx, y) = p(\bx \mid y)P(y)$ — “the mechanism by which the data has been generated”. To classify it must turn this around with **Bayes’ rule**:

$$
P(y = c \mid \bx) = \frac{p(\bx \mid y = c)\,P(y = c)}{p(\bx)}, \qquad p(\bx) = \sum_{c'} p(\bx \mid y = c')\,P(y = c').
$$

Then predict $y = 0$ if $P(y = 0 \mid \bx) > P(y = 1 \mid \bx)$ and $y = 1$ otherwise. The denominator $p(\bx)$ is the same for both classes at a given query, so *to find the most probable class it is enough to compare the numerators* $p(\bx \mid y = c)P(y = c)$. A discriminative model like logistic regression estimates $P(y \mid \bx)$ directly and applies the same comparison.

<Callout kind="example" title="Prior versus likelihood">
For one observation, the feature likelihood is 0.6 under class 1 and 0.3 under class 0; the priors are $P(y=1) = 0.2$, $P(y=0) = 0.8$. The products are $0.6 \times 0.2 = 0.12$ and $0.3 \times 0.8 = 0.24$, so

$$
P(y = 1 \mid \bx) = \frac{0.12}{0.12 + 0.24} = \frac13,
$$

and the most-probable-class rule predicts class 0. Comparing likelihoods alone (0.6 > 0.3) would predict class 1 — it ignores how rare class 1 is.
</Callout>

<Callout kind="warning">
A discriminative classifier need not output probabilities at all — a direct boundary rule is also discriminative. And “generative” does not mean it learns $P(y \mid \bx)$ first: it models the features within each class and obtains the posterior afterwards. For continuous features the likelihoods are *density* values, which can exceed 1.
</Callout>

## Where learning fits

The big picture separates a **task** — which needs a mapping (a model) from data described by features to outputs — from the **learning problem** of obtaining that mapping from training data. This week fills in each piece for classification:

- **Models**: a linear boundary from class means (lesson 2), logistic regression (lessons 3–5), and distance-based classifiers — nearest centroid and k-NN (lessons 11–18).
- **Evaluation**: cross-validation, confusion matrices, precision/recall/F1 and ROC curves (lessons 6–9).
- **Data issues**: feature types, missing values and scaling (lessons 7, 10, 15).

<Callout kind="key">
A classifier maps features to one of a finite set of classes; scores, probabilities and labels are different outputs joined by a decision rule. Discriminative methods learn the boundary or $P(y \mid \bx)$ directly; generative methods model $p(\bx \mid y)$ and $P(y)$ and use Bayes’ rule — compare $p(\bx \mid y)P(y)$, not the likelihoods alone.
</Callout>
