## Strengths and weaknesses

| Advantages | Disadvantages |
| --- | --- |
| can be very accurate | slow at query time: the basic algorithm scans the entire training set |
| no training time | the curse of dimensionality (lesson 18) |
| can approximate complex target functions | treats all attributes as equally important — easily fooled by irrelevant ones (remedy: selection or weights) |
|  | noisy instances (remedy: more neighbours) |
|  | needs homogeneous feature types and scales (lesson 15); finding the best k requires search |

When to consider nearest neighbour: instances map to points in $\R^d$, fewer than about 20 attributes (or they can be reduced), lots of training data, and no need for an explanatory model.

## Why training error is the wrong question

Lazy learners build no explicit model, so how do we evaluate them? Not on the training set: with 1-NN, every training example is its own nearest neighbour at distance 0, so **training error is always zero** (for distinct inputs; conflicting duplicates are the exception). With larger k, overfitting is still hard to see.

The remedy is to make sure the point being predicted is *not* in the reference set. **Leave-one-out cross-validation** predicts each example from all the others,

<p style={{ textAlign: 'center' }}>$(\bx_1, y_1), \dots, (\bx_{i-1}, y_{i-1}), (\bx_{i+1}, y_{i+1}), \dots, (\bx_m, y_m),$</p>

and averages the errors. For k-NN it is easy to define and “fast — no models to be built”: just remove one point from the stored set.

<Callout kind="example" title="Memorising is not predicting">
$(x, y) = (0, 0), (1, 1), (3, 1), (4, 0)$. Each point retrieves itself, so 1-NN training error is 0. Leave-one-out:

| held out x | actual y | nearest remaining x | prediction | correct? |
| --- | --- | --- | --- | --- |
| 0 | 0 | 1 | 1 | no |
| 1 | 1 | 0 | 0 | no |
| 3 | 1 | 4 | 0 | no |
| 4 | 0 | 3 | 1 | no |

LOOCV error is $4/4 = 1$. Memorising the labels and predicting held-out labels are different achievements.
</Callout>

<Callout kind="warning">
If LOOCV is used to *choose* k, its score is selection evidence, not a final estimate — keep a separate test set. Any learned preprocessing (scaling, imputation) must also exclude the held-out point. And k cannot exceed the $m - 1$ points left in each fit.
</Callout>

## Cheap to fit, expensive to query

- Storing the training set costs $O(md)$ memory. A brute-force query computes $m$ distances: $O(m)$ when treating $d$ as fixed, or $O(md)$ for coordinate-wise distances. Picking the $k$ smallest does not need a full sort.
- Brute-force LOOCV makes $m(m-1)$ query-to-reference comparisons: $O(m^2d)$. “No model to train” is not “free evaluation”.
- Tree-based search (e.g. k-d trees) can answer queries in about $O(\log m)$, but does not work well beyond roughly 10 dimensions; approximate nearest-neighbour methods can then speed things up by orders of magnitude. Above about 20 dimensions k-NN itself tends not to work well — the subject of lesson 18.

<Callout kind="key">
1-NN memorises: its training error is zero whatever the data, so training accuracy says nothing about generalisation. Leave-one-out CV predicts each point from the others — easy for k-NN because there is no model to refit — and it costs $O(m^2d)$ by brute force. k-NN shifts all the cost from training to querying.
</Callout>
