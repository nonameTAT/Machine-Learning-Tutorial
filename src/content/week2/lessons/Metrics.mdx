## Decide what “positive” means

In a binary task one class is designated **positive** ($y = 1$) and the other **negative**. “Positive” is a label, not a judgement — in a cancer screen, “positive” is the bad news. Sometimes both classes matter equally (dog vs cat); sometimes one mistake is much costlier than the other: telling a patient they are healthy when they have cancer is worse than a false alarm. A single count of “mistakes” hides that difference.

## Four counts: the confusion matrix

Every prediction falls into one of four cells:

- **True positive (TP)**: actually positive, predicted positive.
- **False negative (FN)**: actually positive, predicted negative — a *missed* case.
- **False positive (FP)**: actually negative, predicted positive — a *false alarm*.
- **True negative (TN)**: actually negative, predicted negative.

| actual ↓ / predicted → | positive | negative |
| --- | --- | --- |
| positive | TP | FN |
| negative | FP | TN |

This contingency table is the **confusion matrix**. Here rows are the actual classes and columns the predictions.

<Callout kind="warning">
Other books and software transpose it. Always read the axis labels before reading off FP and FN.
</Callout>

## Each metric divides by a different population

**Accuracy** on a test set is the fraction of correct labels; classification **error** is $1 - \Acc$:

$$
\Acc = \frac{1}{|\text{Test}|}\sum_{x\in\text{Test}} \Ind[\hat c(x) = c(x)] = \frac{\TP + \TN}{\TP + \TN + \FP + \FN}.
$$

Precision and recall zoom in on the positive class, but condition on different sets:

$$
\Prec = \frac{\TP}{\TP + \FP}\;\;\text{(predicted positives)}, \qquad \Rec = \TPR = \frac{\TP}{\TP + \FN}\;\;\text{(actual positives)}.
$$

| Metric | Denominator counts… | Question answered |
| --- | --- | --- |
| Accuracy | all cases | how many labels were right? |
| Precision | the predicted-positive column | when it says “positive”, how often is it right? |
| Recall / sensitivity / TPR | the actual-positive row | how many of the real positives did it find? |

The **F1 score** combines precision and recall with a harmonic mean, which is dragged down by whichever is smaller.

<Steps>
<Step title="Harmonic mean">
$$
\Fone = \frac{2}{1/\Prec + 1/\Rec} = \frac{2\,\Prec\cdot\Rec}{\Prec + \Rec}\qquad(\Prec, \Rec > 0).
$$
</Step>

<Step title="Substitute the counts">
$$
\frac1\Prec + \frac1\Rec = \frac{\TP + \FP}{\TP} + \frac{\TP + \FN}{\TP} = \frac{2\TP + \FP + \FN}{\TP}.
$$
</Step>

<Step title="Count form">
$$
\boxed{\;\Fone = \frac{2\TP}{2\TP + \FP + \FN}\;}
$$

TN does not appear: F1 ignores correctly rejected negatives. It weights precision and recall equally, which is sometimes not what the task needs.
</Step>
</Steps>

## Worked evaluation

<Callout kind="example" title="Worked example">
Of 100 observations, $\TP = 12$, $\FN = 8$, $\FP = 6$, $\TN = 74$: 20 actual positives, 80 actual negatives.

$$
\Acc = \tfrac{86}{100} = 0.86, \quad \Prec = \tfrac{12}{18} = \tfrac23, \quad \Rec = \tfrac{12}{20} = 0.60, \quad \Fone = \tfrac{24}{38} \approx 0.632.
$$

Predicting *every* observation negative would still score accuracy 0.80 — but recall 0. It misses every positive case.
</Callout>

## Undefined is an answer, not a bug

If no positive predictions are made, precision has denominator 0. If the test set has no positives, recall has denominator 0. Software may substitute a value (often 0, with a warning), but the fraction itself is undefined; report the convention you used. F1’s count form is defined as long as $2\TP + \FP + \FN > 0$.

<Callout kind="key">
Read a confusion matrix by its axes, then ask what each metric divides by: accuracy — everything; precision — predicted positives; recall (TPR) — actual positives; FPR — actual negatives. F1 = $2\TP/(2\TP + \FP + \FN)$ balances precision and recall and ignores TN. Which metric matters depends on which mistakes matter.
</Callout>
