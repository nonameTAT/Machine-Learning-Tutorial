## k controls how local the rule is

k connects directly to the bias–variance trade-off from Week 1:

- **1-NN** perfectly separates the training data (each point retrieves itself): low bias, high variance. A single mislabelled point carves out its own island.
- Increasing $k$ averages over more labels: higher bias, lower variance. The boundary smooths out — and may wash out genuine detail.
- At $k = m$, unweighted k-NN predicts the training-majority class for every query (subject to ties). The neighbourhood is no longer local.

This is also the first remedy for noisy instances: a larger $k$ lets a few wrong labels be outvoted. But how to find the right $k$? Not by training accuracy — use validation or cross-validation (lessons 6 and 17). The trend is a guide, not a theorem: error need not change monotonically with k on every dataset.

## Distance-weighted k-NN

Why should the k-th neighbour count as much as the first? A common answer weights each neighbour by its inverse squared distance and replaces the vote by

$$
\hat y_q = \argmax_{v\in V}\sum_{j\in N_k(\bx_q)} w_j\,\Ind[y_j = v], \qquad w_j = \frac{1}{d(\bx_q, \bx_j)^2}.
$$

These weights depend on the query — they are not the fixed coefficients of a linear classifier.

<Callout kind="example" title="The lesson 14 trace, weighted">
Query 2.8; the three nearest are at distances 0.8 (class 1), 1.2 (class 0), 1.8 (class 0). Weights:

| neighbour | distance | weight 1/d² | class |
| --- | --- | --- | --- |
| x = 2 | 0.8 | 1.5625 | 1 |
| x = 4 | 1.2 | 0.6944 | 0 |
| x = 1 | 1.8 | 0.3086 | 0 |

Class 1 gets 1.5625, class 0 gets 1.0031: weighted 3-NN predicts 1, whereas the unweighted 3-NN vote predicted 0.
</Callout>

For a real-valued target, use a weighted average; the denominator normalises the weights:

$$
\hat f(\bx_q) = \frac{\sum_{j\in N_k(\bx_q)} w_j\,f(\bx_j)}{\sum_{j\in N_k(\bx_q)} w_j}.
$$

With weights, nothing stops us using *all* training examples. Using every example ($k = m$) with this rule is **Shepard’s method**. Unlike the unweighted $k = m$ case, the prediction still varies with the query.

## Two arithmetic traps

- **Zero distance.** If the query coincides with a training point, $1/0^2$ is undefined. State an exact-match rule, e.g. decide among the zero-distance points first (they may still disagree, which needs a tie rule).
- **Already-squared distances.** If you skipped the square root and stored $s_j = d_j^2$, the inverse-square weight is $1/s_j$, not $1/s_j^2$ — that would silently become inverse-fourth-power weighting.

<Callout kind="warning">
Distance weighting does not cure label noise: a single very close mislabelled point receives an enormous weight. Evaluate the complete rule rather than trusting its intuitive appeal.
</Callout>

<Callout kind="key">
Small $k$ follows individual (possibly noisy) labels — low bias, high variance; large $k$ smooths, and at $k = m$ the unweighted rule predicts the majority everywhere. Distance weighting $w_j = 1/d^2$ lets nearer neighbours count more (Shepard’s method uses all $m$). Choose $k$ by validation, and handle zero distances explicitly.
</Callout>
