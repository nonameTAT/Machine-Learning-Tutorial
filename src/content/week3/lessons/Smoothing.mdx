## “Not observed” does not mean “impossible”

No “no” day in the training data was overcast. The raw estimate $\hat P(\text{overcast} \mid \text{no}) = 0/5$ therefore makes the entire “no” score zero for any overcast day, whatever the other features say:

$$
\hat P(x_i \mid v_j) = 0 \;\Longrightarrow\; \hat P(v_j)\prod_i \hat P(x_i \mid v_j) = 0.
$$

With 5 “no” examples, never seeing overcast is weak evidence that it cannot happen. This is the **zero-frequency problem**.

## Pseudo-counts: Laplace and add-α smoothing

Add a pseudo-count to *every possible value* (a version of the Laplace estimator). For a categorical feature with $K_j$ possible values:

$$
\hat P(X_j = v \mid c) = \frac{N_{j,v,c} + \alpha}{N_c + \alpha K_j}, \qquad \alpha > 0.
$$

Laplace smoothing is $\alpha = 1$; a different constant may sometimes be more appropriate. The denominator grows by $\alpha K_j$ because each of the $K_j$ values received $\alpha$ extra counts — so the probabilities still sum to 1.

<Callout kind="example" title="The “no” outlook table">
Counts (sunny, overcast, rainy) = (3, 0, 2) and $K = 3$:

$$
P(\text{sunny} \mid \text{no}) = \tfrac{4}{8}, \quad P(\text{overcast} \mid \text{no}) = \tfrac18, \quad P(\text{rainy} \mid \text{no}) = \tfrac38.
$$

Humidity has only two values, so its denominator is $5 + 2 = 7$, not 8. Use the feature’s set of *possible* values, not the values that happened to appear in this class.
</Callout>

Text models smooth the same way: the Bernoulli model adds two pseudo-documents per class (one containing every word, one containing none), and the multinomial model adds one pseudo-count per vocabulary word. Lessons 14–15 use both.

<Callout kind="note" title="Smoothing changes the model">
It stops unseen events from being treated as impossible; it does not repair dependent features. One zero rules out one class; prediction becomes undefined only when *every* class score is zero. If smoothing is specified, apply it consistently to the whole table.
</Callout>

## Compute in log space

With many features, the product of many small probabilities can *underflow* to 0 in floating point. Since log is strictly increasing, use

$$
\ell_c = \log\hat P(c) + \sum_{j=1}^d \log\hat P(x_j \mid c), \qquad \hat y = \argmax_c \ell_c.
$$

This is the same decision, not a different model. Logs do not solve zero counts: $\log 0$ is still minus infinity.

## The whole algorithm

**Train:** count the classes; fix each feature’s possible values; count values within each class; estimate priors and conditional tables; smooth if required.

**Predict:** for each class start with its log prior; add the log probability of each observed feature value; pick the largest score. Normalise only if a probability is requested. With precomputed tables, one prediction costs $O(Kd)$ for $K$ classes and $d$ features.
