## What should “mixed” mean?

To choose a test, we need to say how much it helps. Start with a single node. Imagine drawing one training example from it at random: you know which node it reached, but not its label. If every label at the node is Yes, there is nothing to guess. If half are Yes and half No, you are as unsure as you can be. We want a number that is 0 for a pure node, largest when the classes are balanced, and that treats the classes symmetrically.

A natural way to build it: measure how *surprising* each outcome is, then average. Seeing a class that makes up 90% of the node is barely surprising; seeing one that makes up 1% is very surprising. The quantity

$$
\text{surprise}(j) = -\log_2 p_j
$$

is 0 when $p_j = 1$ and grows as $p_j$ shrinks. The logarithm is what makes surprises of independent events add up: $-\log_2(pq) = -\log_2 p - \log_2 q$. Base 2 measures it in **bits**: one bit is the surprise of a fair coin flip.

## Entropy is expected surprise

Let the node hold $n$ examples, $n_j$ of them in class $j$, and write $p_j = n_j / n$ (a fraction between 0 and 1, not a percentage). Averaging the surprise over the class distribution gives the **entropy**

$$
H(S) = \sum_{j=1}^{k} p_j\,(-\log_2 p_j) = -\sum_{j=1}^{k} p_j \log_2 p_j,
$$

with the convention $0 \log_2 0 = 0$ (the limit of $p \log p$ as $p \to 0$: a class that never appears contributes nothing). With two classes and positive proportion $p$, this is $H(p) = -p\log_2 p - (1 - p)\log_2(1 - p)$.

<Callout kind="intuition" title="Entropy as a guessing game">
Suppose the classes have probabilities ½, ¼, ¼. Ask “is it class 1?” — half the time you are done after one question; otherwise ask “is it class 2?”. On average you need $\tfrac12 \cdot 1 + \tfrac14 \cdot 2 + \tfrac14 \cdot 2 = 1.5$ yes/no questions, and $H = 1.5$ bits. With four equally likely classes, two questions are always needed: $H = \log_2 4 = 2$. Entropy is the average length of an ideal code for the label — an average over many labels, not a claim that one label uses a fractional number of bits.
</Callout>

## Verify the shape

<Steps>
Why is $H(p)$ largest at $p = \tfrac12$, and only there? Differentiate on $0 < p < 1$.

<Step title="First derivative">
$$
H'(p) = -\log_2 p - \tfrac{1}{\ln 2} + \log_2(1 - p) + \tfrac{1}{\ln 2} = \log_2\frac{1 - p}{p}.
$$
</Step>

<Step title="Stationary point">
$H'(p) = 0 \iff \frac{1 - p}{p} = 1 \iff p = \tfrac12$, where $H = 1$.
</Step>

<Step title="Second derivative">
$$
H''(p) = \frac{1}{\ln 2}\Big(-\frac{1}{1 - p} - \frac{1}{p}\Big) = -\frac{1}{\ln 2\; p(1 - p)} < 0.
$$
</Step>

<Step title="Conclude">
$H$ is strictly concave, so the stationary point is the unique maximum; at the ends $H(0) = H(1) = 0$. Binary entropy lies in $[0, 1]$. With $k$ classes the range is $[0, \log_2 k]$, the maximum reached only at equal proportions.
</Step>
</Steps>

<Callout kind="note" title="A connection to Week 2">
$H(p)$ is the average log loss (in bits) of predicting probability $p$ for labels that really occur with proportion $p$. A pure node lets you predict with certainty at no loss; a balanced node costs one bit per label even with the best constant prediction.
</Callout>

<Callout kind="warning" title="Two kinds of “variability”">
High entropy means the *labels* are evenly spread over classes. It says nothing about how spread out the *feature values* are: a node can be perfectly pure while its examples have wildly different inputs. And entropy ignores sample size: (1, 1) and (50, 50) both have entropy 1, though we trust the second far more. That matters later, when tiny leaves look pure by chance.
</Callout>

<Callout kind="key">
Entropy $H(S) = -\sum_j p_j \log_2 p_j$ is the expected surprise of the label of an example drawn from a node: 0 for a pure node, maximal ($\log_2 k$) when the classes are equally frequent, concave in between. It depends only on the class proportions at the node.
</Callout>
