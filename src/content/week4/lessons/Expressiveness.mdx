## Build the tree by fixing one variable at a time

Before asking how a tree is *learned*, ask what it can *express*. Boolean functions are the cleanest test case: inputs A, B, C, D take the values t or f, and the label is True or False. How would you draw a tree for $A \wedge \neg B$ without guessing its shape?

Pick a variable and substitute both of its values. Each substitution leaves a simpler formula. If a formula has become a constant, that branch is a leaf; otherwise repeat with the next variable. This is exactly what a tree does: each test fixes one variable, and each subtree computes what is left of the function.

<Steps>
<Step title={<>Test A in <M t="A \wedge \neg B" /></>}>
A = f makes the whole conjunction False — a leaf. A = t leaves $\neg B$, which still depends on B.
</Step>

<Step title={<>Test B under A = t</>}>
B = t gives False, B = f gives True. Done: two tests, three leaves.
</Step>

<Step title={<>Now <M t="A \vee (B \wedge C)" /></>}>
A = t already makes it True — stop on that branch. A = f leaves $B \wedge C$: test B (f → False), then C under B = t.
</Step>

<Step title={<>Now <M t="A \oplus B" /> (XOR)</>}>
Fixing A settles nothing: A = t leaves $\neg B$, A = f leaves $B$. Both branches must test B — four leaves.
</Step>

<Step title={<>Finally <M t="(A \wedge B) \vee (C \wedge D)" /></>}>
A = t, B = t gives True. But A = f, and also A = t with B = f, both leave $C \wedge D$. A tree cannot share a subtree between branches, so the C–D subtree is drawn twice.
</Step>
</Steps>

1. A ∨ (B ∧ C): C is tested on only one path. Short-circuiting functions (AND, OR) can stop as soon as the answer is settled.
2. A XOR B: every order gives four leaves, and both variables appear on every path.
3. (A ∧ B) ∨ (C ∧ D): find the order with the fewest leaves and one with more. Variable order changes the size, not the function.
4. Parity of 3 and of 4 variables: 8 and 16 leaves, whatever the order. Each extra variable doubles the tree.

## What makes a tree large?

The size of a tree reflects the *structure* of the function, not the length of its formula. For AND and OR, many inputs are decided by a single variable, so paths end early. For XOR and parity, no proper subset of the variables decides anything: flip any one input and the output flips. So every path must test every variable, and parity of $n$ inputs needs $2^n$ leaves.

Two further costs come from the tree form itself. Subtrees cannot be shared, so a formula like $(A \wedge B) \vee (C \wedge D)$ repeats a piece. And different variable orders give different sizes; finding the smallest tree for a given function or dataset is computationally hard in general (NP-hard), which is one reason learners build trees greedily rather than searching for the optimum.

## Every Boolean function has a tree

<Callout kind="theorem" title="Representational completeness">
Every Boolean function of $n$ variables is computed by some decision tree of depth at most $n$.
</Callout>

**Proof by induction on n.** For $n = 0$ the function is a constant: a single leaf. For $n \ge 1$, test $x_1$. The restrictions

$$
f_t(x_2, \dots, x_n) = f(\text{t}, x_2, \dots, x_n), \qquad f_f(x_2, \dots, x_n) = f(\text{f}, x_2, \dots, x_n)
$$

are functions of $n - 1$ variables, so by the induction hypothesis each has a tree of depth at most $n - 1$. Hang them under the two branches of the $x_1$ test: the result computes $f$ and has depth at most $n$. ∎

The same argument works for any finite number of categorical attributes with finitely many values each: test every attribute in turn, and every complete path identifies one input combination, whose leaf can hold any label.

<Callout kind="warning" title="Can represent ≠ will learn">
Completeness says a suitable tree *exists*. It does not say a greedy learner will find it (lesson 9), that the data determine it (only the observed input combinations constrain the leaves), or that contradictory examples — identical inputs with different labels — can all be classified correctly (lesson 11).
</Callout>

A tree for a Boolean function is built by fixing one variable at a time until what remains is constant.
