## Turn a number into a question

ID3’s tests have one branch per value. A numeric feature such as temperature has too many values for that to make sense, so we ask a yes/no question instead: $x \le t$ or $x > t$. The learner has to choose the threshold $t$.

Only finitely many thresholds are worth considering. Sort the **distinct** observed values $v_1 < v_2 < \dots < v_m$. Any $t$ strictly between $v_i$ and $v_{i+1}$ sends exactly the same training examples left, so there are at most $m - 1$ different partitions, one per gap. The usual convention is the midpoint $t = (v_i + v_{i+1})/2$.

<Callout kind="warning" title="Same training split, different future predictions">
Every threshold in a gap gives the same training partition and the same gain — but not the same predictions for future inputs that fall inside the gap. The midpoint is a convention, not something the data determine. And equal values can never be separated: they fall on the same side of every threshold.
</Callout>

## Why look only at class changes?

Between two neighbouring values with the *same* label, moving the threshold transfers examples of a single class from one side to the other. One can show that the weighted entropy cannot reach its minimum strictly inside such a run, so with distinct values and no extra constraints, a best entropy threshold always lies at a **boundary** where the class changes (a result of Fayyad and Irani). Here the boundaries are 10.65, 12.4, 14.95 and 17.25, and the full table confirms the best one is among them.

Use the shortcut with care. With repeated values, first group equal values and count their classes; a gap next to a mixed group is a boundary too. With constraints such as a minimum leaf size, check all admissible gaps. And never apply a class-change shortcut to a numeric target in regression — there is no “class” to change (lesson 15).

**Cost.** Sorting a feature costs $O(n \log n)$; sweeping the gaps from left to right while updating the left and right class counts costs $O(n k)$ for $k$ classes. A numeric feature can be tested again further down the tree at a different threshold, because each child still contains a range of values.

<Callout kind="note" title="Finding a split is not deciding to keep it">
The best split here isolates one example. That is a correct answer to “which threshold has the largest gain?” and possibly a poor answer to “which split will generalise?”. Split selection and complexity control are separate questions (lessons 10–12).
</Callout>

<Callout kind="key">
A numeric feature becomes a binary test $x \le t$. Only the gaps between neighbouring distinct values matter — at most m − 1 partitions — and, without constraints, the best entropy threshold lies where the class changes. Thresholds in the same gap agree on the training data but not on new inputs; constraints such as a minimum leaf size change which thresholds are allowed, not how they are scored.
</Callout>
