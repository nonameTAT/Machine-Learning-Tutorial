## Why ask several simple questions?

Week 2’s linear classifier draws one boundary through the whole input space, and k-NN keeps every training example and consults its neighbours. A **decision tree** does something in between. It asks a short sequence of simple questions — “is $x_1 \le 2$?” — and each answer narrows down which examples the current one resembles. The questions can differ from branch to branch: once one region is settled, the tree stops asking about it and refines only the regions that are still mixed.

The vocabulary: an **internal node** tests one feature, each **branch** leaving it is one outcome of the test, and a **leaf** holds a prediction. To predict, start at the root and follow exactly one branch at every test until a leaf is reached. A categorical test can have several outcomes (one per value); a numeric threshold test has two.

## One object, three languages

The same tree can be read as a procedure, as a picture of the input space, or as logic. Each view answers different questions.

| View | What the tree is | For the tree below |
| --- | --- | --- |
| Procedure | a sequence of tests ending in a label | ask $x_1 \le 2$; if not, ask $x_2 \le 1$; return a label |
| Geometry | a partition of the input space into regions, one per leaf | the first test cuts the plane vertically; the second cuts only the right half horizontally |
| Logic | one rule per leaf; each rule is a conjunction (AND) of tests | the lower-right leaf is $(x_1 > 2) \wedge (x_2 \le 1) \Rightarrow B$ |

That last point is why trees can represent boundaries no single line could. Each path is an AND of simple conditions; the region predicted as a class is the OR of its paths — a *disjunction of conjunctions*. Simple tests, combined this way, carve out complicated shapes.

## Single-feature tests make axis-parallel cuts

A test such as $x_1 \le t$ cuts the space with a line (in general, a hyperplane) perpendicular to the $x_1$ axis. So with single-feature numeric tests, every leaf region is an **axis-parallel rectangle** in two dimensions — possibly unbounded — and a hyperrectangle in more. A diagonal boundary is therefore something a tree can only approximate, with a staircase of small rectangles.

## Costs and stability

Prediction is cheap: the time is proportional to the number of tests on one path, not to the size of the training set (contrast k-NN). Small trees are easy to inspect and explain. Large trees lose that advantage, and they are **unstable**: a small change in the training sample can change an early split, and everything below that split changes with it. Lesson 10 connects this to high variance.

<Callout kind="warning" title="A leaf describes a region, not an example">
A leaf predicts the same label for every input that reaches it, including inputs unlike any training example. The rectangle is what the tree has learned; the training points inside it are only the evidence.
</Callout>

<Callout kind="key">
A decision tree is a partition of the input space built from simple tests: a procedure (follow the answers), a picture (one region per leaf) and a set of rules (one conjunction per leaf). Single-feature tests give axis-parallel regions, so diagonal boundaries need staircases — and because each question is asked only where it matters, a tree adapts its complexity to the region.
</Callout>
