## From a tree to rules, and pruning the rules

Every root-to-leaf path is a rule: IF (conjunction of tests) THEN (label). Turning the tree into rules gives a different handle for simplification. In **rule post-pruning**, each rule is shortened separately: drop any condition whose removal does not hurt estimated accuracy. That can remove a test near the root from one rule while keeping it in the others — something subtree pruning cannot do, since a node is shared by every path below it.

The price: a shortened rule covers more inputs, so the rules may now overlap (and some inputs may be covered by none). A rule set therefore needs an explicit way to resolve conflicts — for example, order the rules and use the first that fires, with a default class at the end.

## Attributes that are expensive to measure

Some attributes cost money, time or risk to observe — a blood test compared with a temperature reading. When building the tree we may prefer an informative test that is also cheap. One heuristic replaces the gain by

$$
\frac{\operatorname{IG}(S, A)^2}{\operatorname{Cost}(A)}, \qquad \operatorname{Cost}(A) > 0,
$$

which trades information against cost. This is a preference built into the search, not a new definition of information gain, and other trade-offs are possible.

## Mistakes that cost different amounts

Measurement cost concerns *obtaining* an input. Misclassification cost concerns the *consequence of a prediction* — a missed disease versus an unnecessary follow-up. Week 3’s decision rule applies at every leaf: with estimated class probabilities $p_c$ at the leaf and loss $L(a, c)$ for action $a$ when the truth is $c$, choose the action with the least expected loss

$$
R(a) = \sum_c L(a, c)\,p_c.
$$

With false-positive cost 1, false-negative cost 10 and $p(\text{positive}) = 0.2$ at a leaf: predicting positive costs $1 \times 0.8 = 0.8$ in expectation, predicting negative costs $10 \times 0.2 = 2$. The leaf should predict **positive**, although positives are the minority there. Majority voting is the special case of equal costs.

## Missing values: say how they are routed

An example reaches a node that tests an attribute it does not have. Three policies are common:

1. Fill in the most common value among the training examples at that node.
2. During training only, fill in the most common value among examples *of the same class* at that node.
3. Send the example down *every* branch, with weights $q_v$ equal to the fraction of training examples at the node that took branch $v$ (so $\sum_v q_v = 1$). During training, the example then contributes fractional counts to each child, and gains are computed from weighted counts. At prediction time, combine the leaves’ class distributions with the weights that reach them.

<Callout kind="warning" title="Training information that does not exist at prediction time">
Class-conditional filling (policy 2) uses the example’s label. A new example’s label is exactly what we are trying to predict, so that policy cannot be used at prediction time. Specify a policy that is feasible there — node-level filling or fractional routing — rather than quietly using the answer to fill in the input.
</Callout>

## Windowing: learning from a manageable subset

A historical technique for training sets too large to process at once: pick a random subset (the *window*), grow a tree on it, classify the rest of the training set, add some misclassified examples to the window, and repeat. It concentrates effort on the hard cases. Note what its stopping check means: classifying the remaining *training* examples correctly is not evidence of generalisation, and if identical inputs carry conflicting labels the loop needs an error-tolerant stopping rule or it never ends.

<Callout kind="key">
Practical trees need explicit policies. Rules can be pruned one at a time but then need conflict resolution. Measurement cost can shape the search; misclassification cost decides what each leaf predicts, by minimum expected loss. A missing value must be routed by a rule that is feasible at prediction time — fractional routing sends weight down every branch and averages the leaves.
