export const ID3 = `Learn(S, attributes, parent_majority):
    if S is empty:
        return Leaf(parent_majority)
    if every label in S is the same:
        return Leaf(that label)
    majority = most frequent label in S        (fixed tie-break rule)
    if no attribute in 'attributes' splits S:
        return Leaf(majority)
    A = attribute with the largest information gain on S
    node = test on A
    for each value v of A:
        S_v = examples in S with A = v
        node.child[v] = Learn(S_v, attributes − {A}, majority)
    return node`;

## From a representation to an algorithm

Lesson 2 showed that a tree *exists* for any labelling of categorical inputs. Learning has to find a good one from examples. The idea that makes this tractable is recursion: at the root we hold the whole training set $S$. If its labels all agree, we are done. Otherwise we pick one test, send each example down the branch matching its answer, and solve each branch as a smaller, independent problem of exactly the same kind.

This is **top-down induction of decision trees** (TDIDT). **ID3** is the basic version for categorical attributes and labels, choosing tests by information gain (lessons 4–5). **C4.5** extends it with numeric thresholds, gain ratio, missing values and pruning; **CART** uses binary splits and handles both classification and regression.

## Each call sees only its own examples

The crucial detail is *locality*. After the root splits on Outlook, the Sunny branch is a new problem whose data are the five Sunny days — nothing else. Its entropy, its candidate gains and its majority label are computed from those five examples, and the Rain branch may well choose a different attribute.

Three facts hold at every node, and checking them catches most arithmetic slips:

1. **Path invariant.** Every example at a node satisfies every test on the path from the root to it.
2. **Partition invariant.** The children’s example sets are disjoint and together make up the parent’s: their counts add up, class by class.
3. **Attribute use.** A categorical attribute is constant inside each child of its test, so it is removed along that path. A numeric feature is not: a child still holds a range of values and can be split again at another threshold.

The third fact also gives **termination**: with categorical tests each recursive call has one attribute fewer, so the depth is at most the number of attributes. With numeric thresholds, both children of a split are non-empty and strictly smaller than the parent, so the recursion still ends.

## Stopping and labelling leaves

| Situation | What the procedure does | Why |
| --- | --- | --- |
| all labels in S agree | leaf with that label | nothing left to explain |
| no attribute left, or none separates S | leaf with the majority label | a majority label makes the fewest mistakes when all mistakes cost the same |
| S is empty (no training example has this value) | leaf with the parent’s majority | there is no evidence at this node, so fall back on the nearest node that has some |

<Callout kind="warning" title="Zero gain is not the same as “no usable split”">
A test can divide the examples and yet have zero immediate gain. Continuing below it can still reveal structure — XOR is the standard example (lesson 9). Stopping whenever the best gain is zero is an additional early-stopping rule, not part of the basic procedure.
</Callout>

Fix a tie-breaking rule (for example, the first attribute in a fixed order) so the procedure is reproducible: two runs on the same data must give the same tree.

Three tests, five leaves, every training day classified correctly.
</Step>
</Steps>

**Cost.** At a node with $n_S$ examples and $d$ categorical attributes, counting the class of every value of every attribute takes about $O(d\,n_S)$. The nodes at one depth partition the data, so one whole level costs $O(d\,n)$ and the tree costs about $O(d\,n \cdot \text{depth})$. Numeric features add sorting (lesson 8). Predicting follows one path, so it costs $O(\text{depth})$.

<Callout kind="key">
Top-down induction solves one problem by splitting it into smaller problems of the same kind: if the labels agree, make a leaf; otherwise choose a test, partition the examples and recurse. Every score is computed locally, on the examples at the node; the children partition the parent; and majority leaves, parent-majority fallbacks and a fixed tie-break make the procedure well defined and reproducible.
</Callout>
